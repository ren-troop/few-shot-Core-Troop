# 完整对比实验报告：MAML / FO-MAML / Meta-SGD

## 1. 实验目标

本次实验用于比较三类元学习训练方式在跨区域小样本回归任务上的表现：

- 二阶 MAML：保留二阶梯度，`create_graph=True`。
- FO-MAML：一阶近似，`create_graph=False`，忽略 Hessian 项。
- Meta-SGD：在 MAML 基础上额外学习每个参数的内循环学习率。

每种方法同时比较两种 inner loop 更新方式：

- 无半监督：inner loop 只使用有标签的 support set。
- 有半监督：inner loop 使用 support set，并额外引入无标签样本的伪标签损失。

每组方法分别测试 `inner_steps=1,3,5`，因此完整网格为：

`3 种算法 × 2 种半监督设置 × 3 种内循环步数 = 18 组实验`。

## 2. 数据来源与任务构造

实验使用 `sklearn.datasets.fetch_california_housing` 提供的公开 California Housing 数据集。该数据集包含房价预测任务中的区域、人口、住房和收入等特征。本实验将经纬度按分位数切分为多个区域，把每个区域看作一个 task，从而模拟“跨区域小样本预测”问题。

每个 task 的数据被划分为：

- `support set`：用于 inner loop 的任务适应。
- `query set`：用于 outer loop 的 meta loss 计算。
- `ssl_x`：模拟无标签样本，用于半监督 inner loop。

半监督部分采用简单伪标签策略：对每个无标签样本，找到 support set 中特征距离最近的样本，将其标签作为伪标签，并用距离转换出的置信度对伪标签损失加权。

## 6. 主要结论

第一，FO-MAML 是当前结果中最实用的基线。它在 `inner_steps=3` 时得到最低 RMSE，同时训练速度明显快于二阶 MAML 和 Meta-SGD。如果需要在项目中优先选择一个稳定、成本较低的方法，FO-MAML 更合适。

第二，二阶 MAML 并没有因为保留二阶梯度而明显优于 FO-MAML。在本数据和当前超参数下，二阶 MAML 的 `inner_steps=1` 表现接近最优，但增加到 3 步、5 步后误差反而上升，说明更多 inner loop 更新可能导致 support set 上的适应过强，跨区域 query 泛化没有同步提升。

第三，Meta-SGD 在当前设置下不稳定。它学习每个参数的内循环学习率，理论上表达能力更强，但也更容易对学习率范围、outer lr、任务分布和 inner steps 敏感。实验中 Meta-SGD 的 5 步误差明显变大，说明需要继续做学习率约束、调度、正则化或更长训练。

第四，半监督机制带来的提升不是一致的。对二阶 MAML 和 FO-MAML，半监督版本与无半监督版本差距较小；对 Meta-SGD，半监督在 3 步和 5 步时能缓解一部分误差上升，但仍未超过 FO-MAML。这说明当前的最近邻伪标签策略可作为框架验证，但不是最终半监督方案。

第五，内循环步数不是越多越好。FO-MAML 在 3 步达到较好结果，二阶 MAML 在 1 步较好，Meta-SGD 在 5 步明显退化。后续应把 inner steps 作为关键超参数，而不是固定取较大值。

## 8. 如何接入自己的数据

自定义 CSV 至少需要包含：

- 一个区域列，例如 `region_id`，表示每条样本属于哪个区域或任务。
- 一个目标列，例如 `target`，表示要预测的值。
- 若干数值特征列，例如降雨、温度、流量、土壤湿度、遥感指数等。

示例命令：

```bat
cd /d "D:\Desktop\新建文件夹 (2)"
python full_comparison_experiments.py --dataset csv --csv-path "D:\your_data\region_timeseries.csv" --region-column region_id --target-column target --feature-columns "rain,temp,flow,soil_moisture,ndvi" --steps 300 --meta-batch 8 --shots 8 --queries 16 --unlabeled-per-task 16 --inner-steps-list 1,3,5 --output-dir your_full_comparison_outputs --results-csv your_full_comparison_results.csv
```

如果 CSV 中除了区域列和目标列之外都是可用特征，也可以不写 `--feature-columns`，脚本会自动使用其余数值列作为特征。

真实水文或生态数据接入时，需要重点保证三点：

- 同一区域内样本数量要足够支持 `shots + queries + unlabeled_per_task` 的采样。
- 不同区域之间要有明确的任务划分，否则无法形成跨区域 meta-learning 任务。
- 特征列必须是数值型，缺失值和异常值应先完成清洗。
