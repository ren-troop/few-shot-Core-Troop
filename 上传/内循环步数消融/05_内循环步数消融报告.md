# 内循环步数提升实验说明

## 目标

本次实现的是“内循环步数提升”实验，即把元学习任务内更新从单步扩展为多步，并对比：

```text
inner_steps = 1, 3, 5
```

已有主训练脚本 `maml_meta_sgd_framework.py` 支持通过 `--inner-steps` 指定单个步数。本次新增 `inner_steps_ablation.py`，用于在同一配置下自动依次运行 1、3、5 步实验，并把最终结果保存为 CSV，方便比较不同步数对模型适应能力的影响。

## 原理

在 MAML 或 Meta-SGD 中，每个任务分为 support set、query set 和可选的 unlabeled set。

support set 用于 inner loop，也就是任务内快速适应；query set 用于 outer loop，也就是评价适应后的模型表现并更新元模型参数。

单步内循环更新可以写成：

```text
θ' = θ - α ∇θ L_inner(θ)
```

其中：

- `θ` 是模型当前参数。
- `θ'` 是适应某个任务后的参数。
- `α` 是内循环学习率；在 MAML 中是固定值，在 Meta-SGD 中是可学习参数。
- `L_inner` 是任务内更新损失。

当步数提升到 3 步或 5 步时，更新变成递推形式：

```text
θ0 = θ
θ1 = θ0 - α ∇θ0 L_inner(θ0)
θ2 = θ1 - α ∇θ1 L_inner(θ1)
...
θK = θK-1 - α ∇θK-1 L_inner(θK-1)
```

最后用 `θK` 在 query set 上计算 `meta_loss`，再反向更新初始参数 `θ`。

当前框架中的半监督 inner loop 使用：

```text
L_inner = L_support + λ L_ssl
```

其中：

- `L_support` 来自少量有标签 support set。
- `L_ssl` 来自伪标签样本或未标注样本的半监督损失。
- `λ` 对应代码中的 `ssl_weight`，用于控制半监督损失占比。
- `ssl_confidence` 用于降低低置信度伪标签的影响。

## 算法提升逻辑

提升 inner loop 步数的核心逻辑是：单步更新可能不足以让模型适应当前任务，尤其是在任务差异较大、函数幅值较高、噪声较强或真实生态区域差异明显时，1 步更新容易出现拟合不足。

增加到 3 步或 5 步后，模型有更多机会利用 support set 和 unlabeled set 中的信息完成任务内调整，因此可能降低 query set 上的误差，提高新任务适应能力。

但步数不是越多越好。步数增加会带来三类代价：

- 计算时间增加。
- 二阶 MAML / Meta-SGD 下显存占用增加。
- support set 很少时，步数过多可能导致任务内过拟合。

因此本实验不直接假设 5 步一定最好，而是用 1、3、5 步进行消融对比。判断标准主要看：

- `val_query_loss` 是否下降。
- `best_val_query_loss` 是否更低。
- `meta_loss` 是否更稳定。
- `grad_norm` 是否过大或异常波动。

如果 3 步明显优于 1 步，而 5 步提升不明显或更不稳定，则后续正式实验可优先采用 `inner_steps=3`。如果二阶模式显存压力较大，可以增加 `--first-order` 做 FOMAML 近似对照。

## 输入

脚本运行入口：

```bash
python inner_steps_ablation.py
```

常用参数：

```bash
python inner_steps_ablation.py --algorithm meta-sgd --inner-update semi-supervised --inner-steps-list 1,3,5 --steps 300 --meta-batch 8 --shots 5 --queries 10 --unlabeled-per-task 10 --ssl-weight 0.2 --val-tasks 20 --log-every 50 --output inner_steps_results.csv
```

快速测试命令：

```bash
python inner_steps_ablation.py --steps 5 --meta-batch 2 --val-tasks 2 --log-every 1
```

主要输入参数含义：

- `--algorithm`：选择 `maml` 或 `meta-sgd`。
- `--inner-steps-list`：需要比较的内循环步数，默认 `1,3,5`。
- `--inner-update`：选择 `supervised` 或 `semi-supervised`。
- `--steps`：每个步数设置下训练多少个 outer loop step。
- `--meta-batch`：每次 outer update 使用多少个任务。
- `--shots`：每个任务 support set 中有多少个有标签样本。
- `--queries`：每个任务 query set 中有多少个评估样本。
- `--unlabeled-per-task`：每个任务中用于半监督训练的伪标签样本数量。
- `--ssl-weight`：半监督损失权重。
- `--first-order`：启用一阶近似，降低显存和计算成本。
- `--output`：CSV 结果保存路径。

代码中的张量输入格式：

```text
support_x:          (meta_batch, shots, 1)
support_y:          (meta_batch, shots, 1)
query_x:            (meta_batch, queries, 1)
query_y:            (meta_batch, queries, 1)
ssl_x:              (meta_batch, unlabeled_per_task, 1)
ssl_y:              (meta_batch, unlabeled_per_task, 1)
ssl_confidence:     (meta_batch, unlabeled_per_task, 1)
```

## 输出

脚本会输出两类结果。

第一类是终端日志，例如：

```text
[inner_steps=3] algorithm=meta-sgd, device=cpu, inner_update=semi-supervised, first_order=False, meta_batch=8
step=0050 inner_loss=... support_loss=... ssl_loss=... meta_loss=... grad_norm=... val_query_loss=... best_val_query_loss=...
```

第二类是 CSV 文件，默认保存为：

```text
inner_steps_results.csv
```

CSV 中主要包含：

- `inner_steps`
- `inner_update`
- `meta_batch`
- `support_loss`
- `ssl_loss`
- `meta_loss`
- `val_query_loss`
- `best_val_query_loss`
- `grad_norm`
- `meta_lr_mean`
- `meta_lr_min`
- `meta_lr_max`

对比时优先看 `val_query_loss` 和 `best_val_query_loss`，它们表示模型在未参与任务内更新的 query set 上的误差，更能反映泛化效果。

## 当前数据来源

当前代码使用合成 sine wave few-shot 任务作为实验数据来源。

每个任务随机采样一个振幅和相位：

```text
y = A sin(x + φ)
```

其中：

- `A` 表示任务振幅，默认从 `[0.1, 5.0]` 采样。
- `φ` 表示任务相位，默认从 `[0, π]` 采样。
- `x` 默认从 `[-5, 5]` 采样。

这种合成数据的作用不是模拟真实水文过程的完整机理，而是用于快速验证元学习框架是否正确。不同振幅和相位可以近似模拟不同区域、不同站点或不同生态过程之间的任务差异。

半监督样本来自同一个任务函数，但在标签上加入噪声：

```text
ssl_y = true_y + noise
ssl_confidence = exp(-abs(noise))
```

这样可以模拟真实场景中伪标签不完全可靠的问题。

## 如何接入真实数据

真实水文或生态数据接入时，不需要重写 MAML / Meta-SGD 的训练逻辑，主要替换任务采样器。

建议将真实数据整理为统一表格格式：

```text
task_id, split, feature_1, feature_2, ..., feature_n, target, label_available
```

字段含义：

- `task_id`：任务编号，可以对应流域、站点、区域、时间窗口、生态类型或事件类型。
- `split`：样本用途，可以是 `support`、`query` 或 `unlabeled`。
- `feature_1 ... feature_n`：输入特征，例如降雨、温度、蒸散发、遥感指数、土壤湿度、历史水位、历史径流等。
- `target`：有标签样本的真实预测目标，例如径流量、水位、水质指标或生态风险值。
- `label_available`：是否有真实标签。

接入步骤：

1. 按区域、站点、时间窗口或事件类型划分 `task_id`。
2. 每个任务内部划分 support set、query set 和 unlabeled set。
3. 对输入特征做标准化，保证不同量纲的数据可比较。
4. 有标签样本填入 `support_y` 和 `query_y`。
5. 未标注样本填入 `ssl_x`，其 `ssl_y` 可由已有模型、历史模型或伪标签模块生成。
6. 根据伪标签可靠性生成 `ssl_confidence`。
7. 返回统一的 `TaskBatch`，保持字段名与现有代码一致。

如果真实数据是多维特征，需要把当前模型第一层从：

```python
nn.Linear(1, hidden_dim)
```

改为：

```python
nn.Linear(input_dim, hidden_dim)
```

其中 `input_dim` 等于真实数据特征数量。

## 建议实验结论写法

如果实验结果显示 3 步或 5 步优于 1 步，可以写为：

```text
通过将元学习 inner loop 从 1 步扩展至 3 步和 5 步，模型在任务内拥有更充分的参数适应过程。实验中对比不同步数下的 query loss 和验证误差，能够判断多步更新是否有效提升小样本任务适应能力，并分析其与计算成本、训练稳定性之间的权衡。
```

如果 5 步提升不明显，可以写为：

```text
实验结果表明，增加 inner loop 步数能够在一定程度上改善任务适应效果，但过多步数可能带来额外计算开销和过拟合风险。因此后续实验优先采用 3 步作为默认设置，并保留 1 步和 5 步作为消融对照。
```
